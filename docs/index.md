本文档目录是 Pi-Ark 的统一文档入口。README 负责项目概览和快速开始，`docs/` 负责产品行为、实现方式和完整操作说明。

| 文档 | 面向读者 | 内容 |

## 信息来源

文档按以下顺序确认当前行为：

1. `apps/server/src/` 和 `apps/web/src/` 中的当前实现。
2. `scripts/check-*.ts` 与 `scripts/check-ui.mjs` 中的行为检查。
3. `package.json`、`scripts/setup.mjs` 和 `scripts/pi-ark.mjs` 中的命令入口。
4. README 和 `docs/` 中的说明。

代码行为、配置字段、API、存储位置或用户交互发生变化时，同一个 commit 必须更新对应文档。实现与文档出现差异时，应先依据代码和行为检查确认当前状态，然后修正文档。

## 文档职责

- README 只保留项目定位、核心能力、快速开始、常用命令和文档入口。
- 功能与交互设计文档描述用户看到的行为、状态和操作结果。
- 程序实现架构文档描述模块职责、数据流、存储和运行机制。
- 使用手册按照用户完成任务的顺序描述操作步骤。
- Pi 集成调研记录技术选型依据和上游 pi API 背景。

## 维护检查表

提交涉及产品行为的改动前，应完成以下文档检查：

- 新增或修改页面、按钮、对话框、状态提示时，更新功能与交互设计文档和使用手册。
- 新增或修改服务端模块、API、WebSocket 消息、存储格式或数据目录时，更新程序实现架构文档。
- 修改安装、启动、环境变量、CLI 或部署方式时，更新 README、使用手册和程序实现架构文档。
- 修改 pi SDK 的集成方式时，更新程序实现架构文档和 Pi 集成调研。
- 新增文档或调整文档职责时，更新本索引和 `AGENTS.md` 中的文档索引。
